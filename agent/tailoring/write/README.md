# write

Takes each call's JSON output (decided 2026-08-04 — see `prompts/README.md`'s Output format note) and turns it into that call's final artifact.

For the resume and cover letter calls: fill a Jinja2 HTML/CSS template (`templates/resume.html` / `templates/cover_letter.html`, plus shared `templates/_style.html` / `templates/_macros.html` partials) and render it to PDF via Playwright print-to-PDF. **Templating mechanism: Jinja2 with autoescape (decided 2026-08-05)** — chosen over manual string building specifically so escaping (`<`, `>`, `&`, quotes — the deterministic-code job LaTeX-escaping used to fill, see `../README.md`, `../../CLAUDE.md`) is handled by the templating engine automatically rather than relying on every interpolated field being escaped by hand; verified against real LLM-shaped input (`<`/`&`-containing strings render as literal text, not markup). `write_resume(resume, personal, output_path)` and `write_cover_letter(letter, personal, company, output_path)` in `write.py` take the already-parsed `RESUME_SCHEMA` / `COVER_LETTER_SCHEMA`-shaped dicts (schema in `prompts/README.md`'s Resume schema note) plus `profile.json`'s `personal` block (name/email/phone/location/github/linkedin, shared header on both documents) and render them directly — no intermediate escaping step in `write.py` itself. The templates' structure carries over from the old LaTeX-era design conceptually, just not its macro syntax: one block per `projects[]` entry (name, dates, tech, description, bullets, with `repo` linked off the last bullet and `status` folded into the name when present); `skills` grouped by category into one line each (`_category_label()` in `write.py` maps known category keys like `ai_ml`/`devops` to `AI/ML`/`DevOps` rather than a naive title-case, since profile.json's actual keys don't title-case cleanly); `certifications[]` filling a Training & Certificates section. The old `resume_template.tex`/`cover_template.tex` LaTeX files are deleted, fully superseded.

**One-page enforcement (decided 2026-08-04): render first, then check the rendered PDF's page count via `pypdf`**, since Playwright's `page.pdf()` doesn't report a page count directly the way `pdflatex` did. Rendering deliberately does **not** clip overflow with CSS — an earlier draft used `overflow: hidden` on the page body to force a single page, but that was rejected: it silently truncates content instead of surfacing the failure, and a resume cut off mid-sentence must never ship unnoticed. Content is left free to flow past one page; a resulting page count other than 1 logs a warning and returns `None` instead of a path, rather than a hard compile failure the way a broken LaTeX macro would have been. Routing that `None` onward to the user (the email + approve/reject step described in `../README.md`) isn't built yet — that's `review_gate`'s job, not this module's.

For the application call, the JSON (`{field_id: answer}`) is handed to `form_automation/` directly — no template, no PDF.

**Not yet built:** the orchestration that turns each LLM call's raw JSON *string* response (`llm/client.py`'s return value) into the parsed dict `write_resume()`/`write_cover_letter()` expect, and calls the right one per posting. `write.py` has been exercised directly with hand-built schema-shaped dicts (including `<`/`&`-bearing strings, to confirm escaping) and real `profile.json` contact data — not yet against an actual Ollama response. See `../README.md`.
