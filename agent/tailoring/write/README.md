# write

Takes each call's JSON output (decided 2026-08-04 — see `prompts/README.md`'s Output format note) and turns it into that call's final artifact.

For the resume and cover letter calls: parse the JSON, escape each string field for HTML (`<`, `>`, `&`, `"`, `'`) — deterministic code's job, not the model's, the same role LaTeX-escaping used to fill before the 2026-08-04 Playwright pivot (see `../README.md`, `../../CLAUDE.md`) — then fill an HTML/CSS template and render to PDF via Playwright print-to-PDF (`write.py`). The templating mechanism itself (Jinja2 with autoescape vs. manual string building) isn't decided yet. For the resume specifically (schema in `prompts/README.md`'s Resume schema note), the template's structure carries over from the old LaTeX-era design conceptually, just not its macro syntax: one block per `projects[]` entry (name, dates, tech, description, bullets, with `repo` linked off the last bullet and `status` folded into the name when present); `skills` grouped by category into one line each; `certifications[]` filling a Training & Certificates section (previously static content in the old template — now one block per entry).

**One-page enforcement (decided 2026-08-04): render first, then check the rendered PDF's page count via `pypdf`**, since Playwright's `page.pdf()` doesn't report a page count directly the way `pdflatex` did. `write()` deliberately does **not** clip overflow with CSS — an earlier draft used `overflow: hidden` on the page body to force a single page, but that was rejected: it silently truncates content instead of surfacing the failure, and a resume cut off mid-sentence must never ship unnoticed. Content is left free to flow past one page; a resulting page count other than 1 logs a warning and returns `None` instead of a path, rather than a hard compile failure the way a broken LaTeX macro would have been. Routing that `None` onward to the user (the email + approve/reject step described in `../README.md`) isn't built yet — that's `review_gate`'s job, not this module's.

For the application call, the JSON (`{field_id: answer}`) is handed to `form_automation/` directly — no template, no PDF.

`write()` (in `write.py`) currently HTML-escapes its input, renders it through Chromium, and enforces the one-page check described above — but it still takes one raw `llm_text` string, not the structured per-call JSON described above. The JSON-to-template mapping (per-project blocks, grouped skills, the certifications section) isn't implemented yet — today's HTML wrapper is a generic one-block dump, not the resume/cover-letter template structure. See `../README.md`.
